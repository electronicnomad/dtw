REFERENCE · STANFORD D.SCHOOL DESIGN THINKING BOOTLEG DECK

스탠퍼드 d.school 디자인 씽킹 38개 방법론 가이드

스탠퍼드 대학교 d.school이 디자인 프로젝트와 수업을 위해 정리한 38개 방법론(Bootleg Cards)을 한국어로 옮기고 실행 팁을 덧붙인 참고 문서입니다. 원저작물은 CC BY-NC-SA 4.0으로 배포되며, 이 문서도 같은 조건을 따릅니다(출처 및 라이선스). 과제 단계와 상황에 맞는 도구를 골라 활용할 수 있습니다.

Original Work Hasso Plattner Institute of Design at Stanford (Bootleg 2018)
Method Catalog 5개 모드 · 총 38개 실무 도구 요약 및 진행 팁
License Scope CC BY-NC-SA 4.0 (비영리 · 동일조건변경허락)
Mode 01

공감 (Empathize) 도구 8선

EM-01

초심자의 시선 갖기

Assume a Beginner’s Mindset

기존 경험과 업무 지식을 잠시 내려놓고, 처음 접하는 사람의 시선으로 사용자의 환경을 살펴봅니다.

실행 팁: "당연히 알 것"이라는 가정을 거두고, "왜 사용자는 저 버튼을 먼저 누를까?"처럼 기본적인 질문부터 던집니다.
EM-02

What? How? Why? 관찰법

What? How? Why?

관찰 대상을 3단계로 나누어 기록합니다. What(무엇을 하는가), How(어떻게 행동하는가), Why(왜 그렇게 행동하는가·감정).

실행 팁: 장면 하나를 보더라도 관찰된 사실(What)에서 행동 방식(How)을 거쳐 행동 이유(Why) 순으로 추론을 넓혀 갑니다.
EM-03

공감 인터뷰 준비

Interview Preparation

인터뷰 질문을 미리 모은 뒤 주제별로 묶고, 대화 흐름(도입 -> 신뢰 형성 -> 심층 질문 -> 마무리)에 맞춰 순서를 정합니다.

실행 팁: 예/아니오로 끝나는 단답형 질문을 덜어내고, "그때 어떤 생각이 드셨나요?" 같은 개방형 질문으로 바꿉니다.
EM-04

공감 인터뷰 진행 기법

Interview for Empathy

실제 경험담을 이끌어내는 질문을 던지고, 잠시 침묵이 흐르더라도 상대가 생각을 정리해 말할 때까지 기다립니다.

실행 팁: 일반론("보통 어떻게 하시나요?") 대신 구체적 일화("가장 최근에 번거로웠던 상황을 들려주세요")를 묻습니다.
EM-05

극단 사용자 탐색

Extreme Users

평균적인 사용자 대신 서비스를 아주 자주 쓰는 헤비 유저나 아예 쓰지 않는 비사용자를 관찰해 일반 인터뷰에서 잘 드러나지 않는 니즈를 찾습니다.

실행 팁: 극단 사용자가 겪는 불편이나 임시 우회 방법(Workaround)을 풀면 일반 사용자의 편의성도 함께 높아집니다.
EM-06

스토리 공유 및 기록

Story Share-and-Capture

인터뷰를 마친 팀원들이 현장에서 들은 발언과 인상적인 장면을 포스트잇에 적어 공유하고 보드에 분류합니다.

실행 팁: 실제 발언 인용구와 관찰한 행동을 포스트잇 한 장에 하나씩 그대로 적어 현장 맥락을 남깁니다.
EM-07

유사 영역 유추

Analogous Empathy

우리 분야와 업종은 다르지만 '핵심 감정이나 제약 조건'이 비슷한 다른 현장을 관찰해 해결 단서를 얻습니다.

실행 팁: 응급실의 환자 인계 절차를 개선하기 위해 F1 레이싱 피트스톱 팀의 협업 동선을 관찰하는 식입니다.
EM-08

공감 프로브 (자기 기록 조사)

Empathy Probe

관찰자가 동행하기 어려운 시간대나 공간에서는 사용자에게 메모지나 사진 기록 과제를 주어 직접 일상을 남기게 합니다.

실행 팁: 하루 중 업무가 가장 막혔던 순간을 사진 3장과 짧은 메모로 남겨 달라고 요청해 보세요.
Mode 02

정의 (Define) 도구 9선

DF-01

고객 여정 맵

Journey Map

사용자가 경험하는 시간 흐름(시작 전 -> 이용 중 -> 종료 후)을 단계별로 나누고 각 구간의 감정 높낮이를 표시합니다.

실행 팁: 피로와 불편이 가장 크게 쌓이는 병목 지점(Pain Point)이 우선적으로 다룰 개선 구간입니다.
DF-02

10의 거듭제곱 (규모 전환)

Powers of Ten

문제를 바라보는 규모를 아주 작게 줄이거나(단일 순간·개인) 크게 넓혀 보며(장기·대규모) 다른 각도의 단서를 찾습니다.

실행 팁: "이 절차를 10초 안에 끝내야 한다면?" 또는 "10만 명이 동시에 요청한다면?"처럼 조건을 바꿔 질문해 보세요.
DF-03

2x2 매트릭스

2x2 Matrix

서로 다른 두 기준축(X축, Y축)을 놓고 인터뷰 자료나 현상을 4분면으로 배치해 패턴과 빈 영역을 살펴봅니다.

실행 팁: '속도 vs 정확도', '공식 절차 vs 비공식 소통'처럼 축을 바꿔 가며 의미 있는 묶음을 찾아보세요.
DF-04

왜-어떻게 사다리 타기

Why-How Laddering

'Why'를 물어 상위의 목적과 이유로 올라가고, 'How'를 물어 하위의 구체적 수단으로 내려가며 문제의 추상도를 조절합니다.

실행 팁: 문제 범위가 너무 좁으면 위로(Why), 너무 추상적이면 아래로(How) 한 단계씩 옮겨 적정 수준을 찾습니다.
DF-05

관점 정의 (POV) 문장

Point of View (POV)

[특정 사용자]는 [필요]가 필요하다. 왜냐하면 [발견한 인사이트] 때문이다 — 세 요소로 핵심 문제를 한 문장으로 정리합니다.

실행 팁: '필요' 자리에 기능 명사(앱, 대시보드) 대신 동사(상태를 확인하다, 안심하다)를 넣어야 특정 해법에 미리 갇히지 않습니다.
DF-06

디자인 가이드라인 수립

Design Guidelines

이후 어떤 형태(앱, 업무 규칙, 대면 서비스)로 풀더라도 지켜야 할 3~4가지 설계 기준을 먼저 정합니다.

실행 팁: "사용자에게 추가 문장 입력을 요구하지 않는다", "3초 안에 진행 상태를 알 수 있게 한다"처럼 확인 가능한 문장으로 적습니다.
DF-07

HMW (“어떻게 하면 ~할 수 있을까?”)

“How Might We” Questions

POV에서 확인한 문제와 제약을 여러 해결 아이디어가 나올 수 있는 열린 질문 형태로 바꿉니다.

실행 팁: How(해법을 찾아본다), Might(여러 가능성을 열어 둔다), We(팀이 함께 푼다)라는 협력적 태도를 담습니다.
DF-08

예상 밖 관찰에서 인사이트 찾기

Surprise-to-Insights

관찰 과정에서 팀의 사전 예상과 달랐거나 의아하게 느껴졌던 사용자의 행동을 집중적으로 살펴봅니다.

실행 팁: "내부 가정이 빗나간 지점"을 파고들면 기존 방식에서 놓치고 있던 실질적인 개선 기회를 찾기 쉽습니다.
DF-09

콘셉트 요약하기

Describe Your Concept

선정한 아이디어를 논의 직후 정리합니다. 이름, 대상 사용자, 기대 효과, 작동 방식을 적고 핵심 기능 하나로 간추립니다.

실행 팁: 적어 본 콘셉트가 앞서 정의한 사용자 문제와 잘 이어지지 않는다면 후보 목록으로 돌아가 다른 대안을 다시 검토합니다.
Mode 03

발상 (Ideate) 도구 6선

ID-01

스토크 (짧은 활력 활동)

Stoke Activities

아이디어 발산 직전에 2~3분간 자리에서 일어나 박자를 맞추거나 단어를 이어 가는 짧은 활동으로 굳은 분위기를 풀어 줍니다.

실행 팁: 단어 연상 릴레이 등 가벼운 활동으로 실수해도 부담 없는 분위기를 먼저 만듭니다.
ID-02

브레인스토밍

Brainstorming

평가는 잠시 미루고 대안 생성에 집중하는 15~30분 활동입니다. HMW 질문을 기준으로 떠오르는 대안을 포스트잇에 빠르게 적습니다. 기본 7원칙: 1. 판단 유예 2. 엉뚱한 발상 환영 3. 동료 생각에 덧붙이기 4. 주제 집중 5. 한 번에 한 명씩 6. 시각화하기 7. 양에 집중.

실행 팁: 7가지 원칙을 잘 보이는 곳에 적어 두고, 발산 도중 성급한 비판이 나오면 수렴 단계에서 다루자고 가볍게 환기합니다.
ID-03

브레인스토밍 촉진 질문

Facilitate a Brainstorm

아이디어가 비슷해지거나 대화가 멈출 때 진행자가 보조 질문이나 가상 조건을 던져 다른 각도의 대안을 이끌어냅니다.

실행 팁: "개발 예산이 0원이라면?", "배달 앱이라면 이 상태를 어떻게 보여 줄까?"처럼 조건을 바꾼 질문을 건네 보세요.
ID-04

아이디어 선별 (기준별 투표)

Brainstorm Selection

무난하고 익숙한 안만 뽑히는 것을 막기 위해 '당장 적용 가능한 안', '가장 새로운 안', '사용자가 가장 반길 안'처럼 기준을 나누어 투표합니다.

실행 팁: 팀원마다 스티커 색상을 구분해(예: 파란색은 빠른 실행형, 주황색은 새로운 시도형) 붙이도록 안내하면 고르게 추려집니다.
ID-05

제약 조건 걸어 보기

Impose Constraints

시간, 비용, 화면 수 등에 의도적인 제한을 두어 익숙한 해결 방식 대신 단순하고 본질적인 대안을 찾게 합니다.

실행 팁: "별도 화면 없이 알림 한 줄만으로 해결해야 한다면?" 같은 제약이 핵심만 남긴 해법을 찾는 데 도움이 됩니다.
ID-06

Yes, And! 이어 붙이기

Yes, And! Brainstorm

즉흥극(Improv)의 대화 원리를 빌려, 앞사람의 의견을 "하지만(No, But)"으로 끊지 않고 "좋아요, 거기에 더해서(Yes, And)"로 이어 갑니다.

실행 팁: 설익은 초기 아이디어에 팀원들이 돌아가며 조건을 보태어 실행 가능한 형태로 발전시킬 때 유용합니다.
Mode 04

프로토타입 (Prototype) 도구 8선

PR-01

공감을 위한 프로토타입

Prototype for Empathy

해결책을 확정하기 위해서가 아니라, 사용자의 구체적인 반응과 기준을 더 깊이 듣기 위해 만드는 대화용 모형입니다.

실행 팁: 간단한 모형을 보여 주고 "이 화면을 보시면 어떤 생각이 먼저 드세요?"라고 물어 평소 말로 꺼내지 않던 반응을 확인합니다.
PR-02

바디스토밍 (현장 재연)

Improvise to Life

책상에서 그리는 대신 팀원들이 직접 사용자와 담당자가 되어 실제 공간에서 움직이며 서비스 흐름을 재연합니다.

실행 팁: 직접 동선을 따라 움직여 보면 문서에서는 보이지 않던 대기 지점이나 응대 순서의 어색함이 바로 드러납니다.
PR-03

장면/소품/역할 시뮬레이션

Scenes / Props / Roles

공간(Scene), 간단한 소품(Props: 상자, 표지판 등), 배역(Role)을 정해 여러 사람이 얽힌 서비스 시나리오를 점검합니다.

실행 팁: 상자 몇 개로 안내 데스크나 키오스크를 세워 두고 동료를 손님으로 맞이해 어디서 설명이 막히는지 확인합니다.
PR-04

결정을 위한 비교 프로토타입

Prototype to Decide

팀 안에서 의견이 갈리는 두 가지 안(A안 vs B안)을 각각 간단한 모형으로 만들어 나란히 두고 사용자 반응을 비교합니다.

실행 팁: 1시간 동안 말로 우열을 가리기보다 10분씩 만든 두 모형을 옆 조 동료에게 보여 주는 편이 훨씬 빠르게 결론에 닿습니다.
PR-05

단일 변수 분리 검증

Identify a Variable

서비스 전체를 만들지 않고, 지금 확인하려는 '핵심 가설 하나(예: 버튼 문구 이해도, 사용 의향)'만 떼어내어 모형으로 만듭니다.

실행 팁: 부가 요소를 덜어내고 확인하려는 요소 하나에 집중해야 테스트 결과의 원인을 분명하게 해석할 수 있습니다.
PR-06

오즈의 마법사 프로토타이핑

Wizard of Oz

사용자 눈앞의 화면은 자동화된 기능처럼 보이게 두고, 실제 처리는 뒤에서 사람이 수동으로 응답해 개발 전에 효용을 검증합니다.

실행 팁: 자동 알림 봇을 개발하기 전에 담당자가 정해진 양식으로 직접 메시지를 보내 보며 실제 반응부터 확인하는 방식입니다.
PR-07

비디오 프로토타입 촬영

Shooting Video

스마트폰으로 사용자가 솔루션을 만나 문제를 해결하는 1분 내외의 장면을 촬영해 서비스 맥락과 전달력을 점검합니다.

실행 팁: 세부 기능 나열보다 '도입 전 겪던 불편과 도입 후 달라진 업무 흐름의 대비'가 드러나게 구성합니다.
PR-08

비디오 편집 및 핵심 장면 요약

Editing Video

촬영본에서 부연 설명을 덜어내고 문제 상황과 해결 순간이 드러나는 30초 내외의 핵심 장면만 묶어 공유합니다.

실행 팁: 긴 문서 설명보다 실제 사용 맥락이 담긴 짧은 영상 한 편이 타 부서 이해관계자의 이해를 돕는 데 효과적입니다.
Mode 05

테스트 (Test) 도구 7선

TE-01

사용자 테스트 (Show, Don’t Tell)

Testing with Users

프로토타입을 건네주고 사용법을 미리 설명하지 않습니다. 사용자가 스스로 살펴보며 겪는 시행착오를 그대로 관찰합니다.

실행 팁: 사용자가 "이건 어떻게 쓰는 건가요?"라고 물으면 곧바로 답하기보다 "어떻게 동작할 것으로 보이시나요?"라고 되물어 보세요.
TE-02

사용자 참여형 프로토타이핑

User-Driven Prototyping

완성된 안을 보여 주는 대신 사용자에게 종이 카드나 구성 요소를 건네고 "원하는 순서나 화면을 직접 배치해 보세요"라고 요청합니다.

실행 팁: 사용자가 먼저 고르는 항목과 배치 순서를 보면 무엇을 가장 중요하게 여기는지 자연스럽게 드러납니다.
TE-03

피드백 캡처 매트릭스

Feedback Capture Matrix

보드를 사분면으로 나누어 좌상 [+ 좋았던 점], 우상 [Δ 보완할 점], 좌하 [? 질문], 우하 [전구: 새 아이디어]로 반응을 기록합니다. (본 워크숍 워크시트는 Δ와 전구 대신 -와 ! 기호를 사용합니다.)

실행 팁: 보완할 점(-)과 질문(?)이 구체적으로 모일수록 다음 수정 방향을 잡기가 수월해집니다.
TE-04

스토리텔링 공유

Storytelling

기능 목록만 나열하지 않고 '사용자가 겪던 상황 -> 핵심 문제 -> 프로토타입 시연 -> 테스트에서 확인한 배움' 순서로 전달합니다.

실행 팁: 구체적인 사용자 사례로 이야기를 시작하면 다른 직무 참석자도 문제의 맥락을 빠르게 이해할 수 있습니다.
TE-05

I Like, I Wish, What If 회고

I Like, I Wish, What If

세션을 마친 뒤 "좋았던 점(I Like)", "아쉬웠거나 바라는 점(I Wish)", "실무에 적용해 볼 제안(What If)" 세 항목으로 의견을 나눕니다.

실행 팁: 개인을 탓하지 않으면서도 다음 세션이나 후속 업무에 반영할 개선점을 차분하게 모을 수 있는 회고 방식입니다.
TE-06

정성 인사이트와 정량 데이터 결합

Empathetic Data

인터뷰와 관찰에서 찾은 정성적 가설을 설문이나 사용 로그 같은 수치 데이터와 함께 대조해 타당성을 점검합니다.

실행 팁: "왜 그런 행동을 하는가(Why)"는 인터뷰로 파악하고, "얼마나 자주 발생하는가(How many)"는 데이터로 확인합니다.
TE-07

아이디어 포트폴리오 점검

Review Your Portfolio

팀이 추린 해법들이 단기 소폭 개선에만 몰려 있지 않은지, 즉시 실행 과제와 중장기 실험 과제가 균형을 이루는지 살핍니다.

실행 팁: 예컨대 단기 개선안 70%, 중기 확장안 20%, 장기 실험안 10%처럼 조직 여건에 맞는 비중을 정해 두고 점검합니다.
