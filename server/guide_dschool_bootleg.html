Stanford d.school Bootleg Guide 38 Core Methods
운영 가이드 IDEO U 가이드 프레젠테이션으로 돌아가기
Reference: d.school Design Thinking Bootleg Deck (Stanford University)

스탠퍼드 d.school Design Thinking 툴킷 완벽 해설서

스탠퍼드 대학교 d.school이 실전 디자인 프로젝트와 수업을 위해 고안한 38개 핵심 방법론(Bootleg Cards)을 한국어로 체계화한 도구 해설서입니다. 프로젝트의 목적과 단계에 맞추어 주머니에서 카드를 꺼내듯 적절한 툴을 선택해 활용할 수 있습니다.

Mode 01

공감 (Empathize) 도구 8선

EM-01

초심자의 마음가짐 갖기

Assume a Beginner’s Mindset

기존의 경험과 지식, 선입견을 의도적으로 지우고 어린아이의 눈으로 사용자의 환경을 바라봅니다.

실행 팁: "당연히 알 것"이라는 전제를 버리고, "왜 사용자가 저 버튼을 먼저 누를까?"라는 기초적인 질문부터 던집니다.
EM-02

What? How? Why? 관찰법

What? How? Why?

관찰 대상을 3단계로 분석합니다. What(무엇을 하는가), How(어떻게 행동하는가), Why(왜 그렇게 행동하는가/감정).

실행 팁: 사진 한 장을 보며 구체적 사실(What)에서 행동 양식(How)을 거쳐 이면의 내면 동기(Why)로 사다리를 탑니다.
EM-03

공감 인터뷰 준비

Interview Preparation

인터뷰 질문 브레인스토밍 후 테마별 그룹화, 그리고 시간 순서(도입 -> 신뢰 형성 -> 심층 탐색 -> 랩업)로 재배열합니다.

실행 팁: 예/아니오로 끝나는 폐쇄형 질문을 모두 제거하고, "그때 어떤 기분이셨나요?" 같은 개방형 질문으로 전환합니다.
EM-04

공감 인터뷰 진행 기법

Interviewing for Empathy

스토리를 끌어내는 질문을 던지고, 어색한 침묵을 견디며 사용자가 속마음을 꺼낼 때까지 기다립니다.

실행 팁: 일반론("보통 어떻게 하시나요?") 대신 구체적 일화("가장 최근에 겪었던 불편한 경험을 들려주세요")를 요구하세요.
EM-05

극한 사용자 탐색

Extreme Users

평균적인 사용자가 아닌, 과도하게 서비스를 많이 쓰는 헤비 유저나 아예 거부하는 비사용자를 관찰하여 숨겨진 니즈를 극대화해 포착합니다.

실행 팁: 극한 사용자의 불편함과 우회 행동(Workaround)을 해결하면 일반 사용자에게는 압도적인 편의성이 됩니다.
EM-06

스토리 공유 및 캡처

Story Share-and-Capture

인터뷰를 마치고 돌아온 팀원들이 현장에서 수집한 생생한 이야기와 놀라운 일화를 포스트잇으로 공유하고 벽면에 매핑합니다.

실행 팁: 인용구("그 사람의 육성 그대로")와 행동 묘사를 한 장당 하나씩 기록하여 생동감을 보존합니다.
EM-07

유사 영역 유추

Analogous Empathy

우리 분야와 전혀 다르지만 '핵심 감정이나 제약'이 동일한 이종 산업의 경험을 직접 체험하여 새로운 영감을 얻습니다.

실행 팁: 응급실의 신속 환자 이송 문제를 해결하기 위해 F1 레이싱 피트스톱 팀의 타이어 교체 절차를 관찰합니다.
EM-08

공감 프로브 (다이어리 연구)

Empathy Probe

관찰자가 직접 들어갈 수 없는 사적인 순간에 사용자에게 일기장이나 사진 기록 키트를 주고 스스로 일상을 기록하게 합니다.

실행 팁: 사용자가 무심코 넘기는 하루 중 가장 답답했던 찰나의 사진 3장을 찍어 공유하도록 요청합니다.
Mode 02

정의 (Define) 도구 8선

DF-01

고객 여정 맵

Journey Map

사용자가 경험하는 시간의 흐름(시작 전 -> 경험 중 -> 종료 후)을 단계별로 나누고 각 구간의 감정 고점과 저점을 시각화합니다.

실행 팁: 감정이 가장 바닥으로 곤두박질치는 지점(Pain Point)이 가장 혁신적인 기회의 출발점입니다.
DF-02

10의 거듭제곱 (스케일 전환)

Powers of Ten

문제를 바라보는 스케일을 극단적으로 축소하거나(미시적/개인) 극단적으로 확장하여(거시적/글로벌) 새로운 통찰을 얻습니다.

실행 팁: "이 문제를 해결하는 데 1초밖에 없다면?" 혹은 "이 문제를 100만 명이 동시에 겪는다면?"으로 스케일을 변경해 보세요.
DF-03

2x2 매트릭스

2x2 Matrix

서로 독립적인 두 축(X축, Y축)을 설정하여 인터뷰 데이터나 현상을 4분면으로 분류하고 아무도 점유하지 않은 빈 영역을 탐색합니다.

실행 팁: '속도 vs 정확도', '공식적 vs 비공식적' 등 다양한 대립 축을 교체하며 숨겨진 기회 공간을 발굴합니다.
DF-04

왜-어떻게 사다리 타기

Why-How Laddering

'Why'를 물어 상위의 본질적 의미와 가치로 올라가고, 'How'를 물어 하위의 구체적인 실행 방법으로 내려오며 문제의 층위를 조절합니다.

실행 팁: 문제 정의가 너무 협소하면 사다리를 위로(Why), 너무 추상적이면 사다리를 아래로(How) 이동시키세요.
DF-05

관점 정의 (POV) 공식

Point of View (POV)

[특정 사용자]는 [인간적 필요]가 필요하다. 왜냐하면 [놀라운 인사이트] 때문이다의 3요소로 문제의 핵심을 단문으로 응축합니다.

실행 팁: '필요'에는 솔루션 명사(앱, 대시보드)가 아닌 동사(확인하다, 안심하다)를 넣어야 솔루션 함정에 빠지지 않습니다.
DF-06

디자인 가이드라인 수립

Design Guidelines

향후 어떤 아이디어가 나오더라도 반드시 만족해야 하는 3~4가지 핵심 원칙을 정의합니다.

실행 팁: "사용자에게 추가적인 타이핑을 요구하지 않는다", "3초 이내에 상대방의 상태를 인지시킨다" 등의 측정 가능한 기준을 세웁니다.
DF-07

HMW (“어떻게 하면 ~할 수 있을까?”)

“How Might We” Questions

POV에서 발견된 긴장감과 모순을 창의적인 아이디어가 발산될 수 있는 긍정적인 질문의 형태로 프레이밍합니다.

실행 팁: How(방법이 존재한다), Might(우리 아이디어가 틀릴 수도 있다), We(함께 팀으로 푼다)는 겸손과 도전의 태도를 담습니다.
DF-08

놀라움에서 인사이트로

Surprise-to-Insights

관찰 도중 팀의 상식과 가장 정반대였거나 우리를 가장 당황스럽게 만들었던 사용자의 행동을 집중 분석합니다.

실행 팁: "우리가 틀렸던 순간"이야말로 경쟁사가 절대 발견하지 못한 독점적 비즈니스 기회의 시작점입니다.
Mode 03

발상 (Ideate) 도구 6선

ID-01

스토크 (에너지 점화 게임)

Stoke Activities

아이디어 발산 세션 직전에 2~3분간 몸을 움직이거나 박자를 맞추는 초단기 게임으로 좌뇌의 경직성을 깨부숩니다.

실행 팁: 단어 연상 릴레이, 1부터 20까지 눈치게임 등을 통해 실수해도 웃어넘기는 안전한 분위기를 예열합니다.
ID-02

브레인스토밍 7대 원칙

Brainstorming Rules

1. 판단 유예 2. 거친 아이디어 장려 3. 타인 아이디어에 덧붙이기 4. 한 번에 한 명만 발언 5. 시각화하기 6. 주제 집중 7. 양의 추구.

실행 팁: 7대 원칙을 벽에 크게 붙여두고, 누군가 아이디어를 비판하면 진행자가 원칙 포스터를 가리키며 제지합니다.
ID-03

브레인스토밍 촉진 기법

Facilitate a Brainstorm

아이디어 발산이 정체될 때 퍼실리테이터가 새로운 촉매 질문이나 제약을 투입하여 두 번째 발산의 파도를 만듭니다.

실행 팁: "예산이 0원이라면?", "디즈니랜드라면 이 문제를 어떻게 풀까?" 같은 이질적 프롬프트로 벽을 뚫어줍니다.
ID-04

아이디어 선별 (다각도 투표)

Brainstorm Selection

가장 안전한 아이디어만 뽑히는 것을 막기 위해, '가장 실용적인 것', '가장 대담한 것', '가장 사랑스러운 것' 등 카테고리별로 분산 투표합니다.

실행 팁: 각 팀원에게 파란색 스티커(당장 실행형)와 붉은색 스티커(파격 혁신형)를 구분하여 부여하세요.
ID-05

제약 조건 부여하기

Impose Constraints

시간, 기술, 물리적 비용, 인터페이스 화면 등에 극단적인 제약을 걸어 기존의 틀에 박힌 사고를 강제로 차단합니다.

실행 팁: "화면이 전혀 없는 음성만으로 서비스를 제공해야 한다면?"과 같은 제약이 진짜 창의성을 폭발시킵니다.
ID-06

Yes, And! 확장 발산법

Yes, And! Brainstorm

즉흥극(Improv)의 기본 원리로, 상대방의 아이디어를 절대 "하지만(No, But)"으로 꺾지 않고 "좋아요, 거기에 덧붙여서(Yes, And)"로 빌드업합니다.

실행 팁: 불완전한 아이디어를 집단 지성이 릴레이로 살을 붙여 완성도 높은 컨셉으로 진화시키는 기법입니다.
Mode 04

프로토타입 (Prototype) 도구 8선

PR-01

공감을 위한 프로토타입

Prototype for Empathy

솔루션을 증명하기 위해서가 아니라, 사용자가 무엇을 원하고 어떤 반응을 보이는지 '더 깊은 대화를 이끌어내기 위해' 만드는 거친 모형입니다.

실행 팁: 모형을 쥐여주고 "어떻게 느껴지세요?"라고 물어보며 사용자의 숨겨진 생각을 낚아챕니다.
PR-02

바디스토밍 (온몸으로 구현)

Improvise to Life

종이에 그리는 대신 팀원들이 직접 고객과 서비스 제공자가 되어 실제 물리적 공간에서 연기(Role-play)하며 경험을 시뮬레이션합니다.

실행 팁: 몸을 직접 움직여보면 동선 충돌, 시선의 어색함, 대기 시간의 지루함이 오감으로 드러납니다.
PR-03

장면/소품/역할 시뮬레이션

Scenes / Props / Roles

공간(Scene), 최소한의 도구(Props: 박스, 빗자루 등), 참가자의 배역(Role)을 지정하여 복합적인 서비스 시나리오를 검증합니다.

실행 팁: 박스 몇 개를 쌓아 무인 키오스크를 만들고 동료를 손님으로 맞이하여 프로세스의 막힘을 찾습니다.
PR-04

결정을 위한 프로토타입

Prototype to Decide

팀원들 사이에 논쟁이 벌어지는 두 가지 대안(A안 vs B안)을 각각 초간단 모형으로 제작하여 나란히 놓고 비교 테스트합니다.

실행 팁: 1시간의 회의보다 10분짜리 두 개의 모형 비교가 훨씬 명확하고 빠른 합의를 이끌어냅니다.
PR-05

단일 변수 분리 검증

Identify a Variable

전체 제품을 다 만들지 않고, 우리가 검증하고자 하는 '단 하나의 가설(예: 가격 수용도 or 사용 편의성)'만 격리하여 제작합니다.

실행 팁: 복잡한 기능을 빼고 핵심 인터랙션 하나만 담아야 고객의 반응 원인을 정확히 추적할 수 있습니다.
PR-06

오즈의 마법사 프로토타이핑

Wizard of Oz

앞단(프론트)은 정교한 자동화 시스템처럼 보이게 만들고, 뒷단(서버/AI)은 사람이 수동으로 조작하여 기술 개발 전 가치를 검증합니다.

실행 팁: 인공지능 추천 봇을 만드는 대신, 뒷방에서 팀원이 실시간으로 메시지를 직접 쳐서 고객의 반응을 봅니다.
PR-07

비디오 프로토타입 촬영

Shooting Video

스마트폰으로 미래의 고객이 우리 솔루션을 사용하는 1분짜리 광고 형식의 영상을 촬영하여 가치 전달력을 검증합니다.

실행 팁: 기술적 디테일이 아니라, 고객이 '전에는 고통받다가 제품을 쓰고 행복해지는 전후 대비'에 집중하세요.
PR-08

비디오 편집 및 숏폼 제작

Editing Video

촬영한 푸티지에서 불필요한 설명을 쳐내고 가장 결정적인 사용자 감정 순간 30초만 엮어 핵심 이해관계자에게 공유합니다.

실행 팁: 긴 보고서 50페이지보다 고객의 생생한 감탄이 담긴 30초 영상 클립이 경영진을 즉시 설득합니다.
Mode 05

테스트 (Test) 도구 8선

TE-01

사용자 테스트 (Show, Don’t Tell)

Testing with Users

프로토타입을 건네주고 사용법을 설명하지 않습니다. 사용자가 스스로 만지작거리며 겪는 시행착오를 조용히 관찰합니다.

실행 팁: 사용자가 "이건 어떻게 쓰는 건가요?"라고 물으면 "어떻게 작동할 것 같으세요?"라고 질문으로 되돌려줍니다.
TE-02

사용자 주도 프로토타이핑

User-Driven Prototyping

우리가 만든 것을 보여주는 대신, 사용자에게 여러 가지 부품과 종이를 주고 "원하는 해결책을 직접 만들어보세요"라고 요청합니다.

실행 팁: 사용자가 배치하는 요소의 우선순위와 형태를 통해 그들의 무의식적 가치관을 포착할 수 있습니다.
TE-03

피드백 캡처 그리드

Feedback Capture Grid

사분면을 나누어 [+ 호평], [- 비판], [? 사용자의 질문], [! 새로운 아이디어]로 체계적으로 실시간 피드백을 기록합니다.

실행 팁: 비판(-)과 질문(?)이 많이 쏟아질수록 차기 버전의 개선 방향이 뚜렷해지므로 대환영해야 합니다.
TE-04

스토리텔링 피칭

Storytelling

스펙과 기능을 나열하지 않고, '주인공(사용자)의 결핍 -> 위기 -> 솔루션과의 만남 -> 삶의 변화' 서사 구조로 공유합니다.

실행 팁: 청중이 논리적 잣대를 들이대기 전에 감정적 공감으로 솔루션의 필요성을 체감하게 만듭니다.
TE-05

I Like, I Wish, What If 회고

I Like, I Wish, What If

세션 종료 후 "좋았던 점(I Like)", "아쉬웠거나 바라는 점(I Wish)", "만약 ~라면 어떨까(What If)"의 3단계로 부드럽게 피드백을 나눕니다.

실행 팁: 상대방의 감정을 상하게 하지 않으면서도 건설적인 개선 아이디어를 도출할 수 있는 회고 표준 툴입니다.
TE-06

공감 데이터 정량화

Empathetic Data

질적 인터뷰와 관찰에서 얻은 직관적 통찰을 설문조사, 로그 데이터 등의 수치와 결합하여 가설의 시장성을 검증합니다.

실행 팁: "왜(Why)"는 질적 인터뷰로 파악하고, "얼마나 많이(How many)"는 데이터 분석으로 교차 검증합니다.
TE-07

포트폴리오 리뷰

Review Your Portfolio

팀이 도출한 프로토타입 모음이 점진적 개선에만 치우쳐 있지 않은지, 단기형과 장기 파괴적 혁신형으로 균형을 이루는지 점검합니다.

실행 팁: 단기 안전형 솔루션 70%, 도전적 솔루션 20%, 파괴적 문샷 솔루션 10%의 포트폴리오 밸런스를 맞추세요.
TE-08

반복 이터레이션 설계

Design Next Steps

테스트 결과를 바탕으로 [폐기 / 수정 / 다음 단계 진입]을 결정하고 다음 2주간의 실험 계획을 수립합니다.

실행 팁: "실패는 없습니다. 가설이 틀렸다는 사실을 가장 저렴한 비용으로 빠르게 발견했을 뿐입니다."
